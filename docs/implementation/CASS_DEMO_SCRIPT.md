# CASS 比赛演示脚本

目标：在 3–5 分钟内展示“情境证据 → 规则决策 → 数字人/行程响应 → 游客确认”的连续导览信息流；将真实来源与演示数据明确区分。

## 演示前准备

- 后端设置 `CASS_ENABLED=true`、`CASS_DEMO_ENABLED=true`；不需要 QWeather Key 才能演示模拟天气、客流和预警。
- 在景区运营端发布至少一个 K01 景点，保证游客端可读取已发布目录。
- 如果要演示路线提案及差异确认，提前在游客端打开一个 V2 游览并保存至少两个未完成景点。提案生成仍需要项目现有模型服务可用。
- 如果要展示真实附近景点建议，浏览器需授权定位、定位精度不高于 80 米，且附近 250 米内至少有一个带坐标依据的已发布景点。此项可跳过；模拟定位不会伪装成真实位置。
- QWeather Key 可选。未配置或上游不可用时，实时天气显示为不完整状态，模拟天气演示仍可重复运行。

## 推荐演示顺序

1. 打开 `/tourist`，指出右侧“讲解”栏中的情境面板。说明这是情境信息驱动的服务信息流：游客偏好与时间进入生成式服务，数据来源和有效期由规则通道核验，安全事件由独立调度器抢占。
2. 点击“开启情境导览”。选择剩余时间和兴趣主题，展示理由、规则 ID、数据性质和有效期。若目录坐标具备依据且真实定位满足精度门槛，可先点“按位置选择附近景点”；原始 GPS 只在客户端用于候选计算。
3. 点击“演示雨天讲解适配”。卡片应显示“小雨”“模拟天气”“不作为安全证据”；点击“按演示情境生成讲解”，展示雨天节奏约束进入既有景点问答/RAG 请求。系统不会仅因降雨断言景点室内、开放或安全。
4. 如有活动中的 V2 游览，点击“演示客流变化”，再点“生成路线调整提案”。展示 V01 生成的路线差异和校验结果；由演示者核对后再选择“确认并保存新版本”。没有活动中的 V2 游览时，改用“剩余时间 20 分钟 → 生成路线调整提案”展示同一审核链路。
5. 点击“演示预警抢占”→“继续演示：模拟预警变化”。确认普通讲解状态被安全提醒替代，并看到“演示数据”标签；点击“我已了解”后仍不会自动恢复，再点“继续演示（需再次确认）”，最后显式点击“按演示情境生成讲解”。
6. 回到普通游客问答，输入一个景点问题，演示现有文字/语音回答；播放时演示停止入口，完成后可使用既有重播。说明关闭或不可用 CASS 时，游客原有问答和讲解入口仍保留。

## 答辩时的技术表述

> 我们把景区天气、经核验的景点目录、游客时长与兴趣组织成情境信息流：生成式服务负责内容理解和个性化讲解，确定性规则校验时效、限制安全结论并控制服务优先级，再由统一调度连接数字人、语音和 V01 行程审核。模拟演示用于稳定呈现交互闭环，不包装成现场监测数据。

## 演示故障时的处理

- 天气未配置或不可用：使用内置雨天模拟演示，不现场声称存在实时天气数据。
- 没有合格真实定位或核验坐标：跳过附近景点候选，手动从已发布景点目录选择。
- 没有活动中的 V2 游览：跳过客流提案，使用时间不足的提案场景；若模型服务暂不可用，展示现有差异卡与已有行程版本保护，不宣称提案已生成。
- 模拟安全提醒：只展示本地提示，不拨号、不上传位置、不声称已通知景区或已启动救援。
