# 评委体验系统验收记录

日期：2026-10-29（Asia/Shanghai）<br>
验收重点：找出评委现场操作时会直接感知、足以影响演示观感的严重问题；一般性、低显著度问题不纳入本轮修复。

## 结论

发现并修复 1 项严重体验问题：1000–1399px 桌面窗口打开“实时地图”后，地图工具沿用窄功能栏，地图和说明被挤压、文字换行，形成明显不完整的演示观感。`ChatView` 现在只在地图工具激活时标记 `map-open`，中等宽度桌面将左栏扩至至少 300px（或视口的 26%），保留中间数字人舞台和右侧讲解栏。

## 实际检查

| 环节 | 操作与结果 | 判断 |
|---|---|---|
| 游客首页 | 在浏览器预览打开 `/tourist`；数字人完成加载，主要语音、文字、拍照入口可见 | 未发现足以阻断演示的首页布局问题 |
| 地图工具 | 打开 `/tourist/map`（规范化为 `/tourist?tool=map`）；地图底图、景点标记、缩放、图层切换、路线选择与分区景点列表均出现；工具面板展示完整地图内容 | 首次检查发现桌面窄栏问题，已修复；复验截图中地图完整铺开且可见景点与控制项 |
| 登录保护 | 直接打开 `/admin/dashboard`；未登录时被重定向至 `/admin/login?redirect=/admin/dashboard` | 管理页面不会直接暴露给游客 |
| 游客问题提交失败态 | 在未启动后端的静态预览输入问题并提交；接口返回 HTTP 500，页面保留已有内容、标记回答未完成并提供重试 | 只确认失败提示和保留内容；不能据此判断真实后端问答链路 |
| 演示数据标识 | 地图明确将 3,731 人客流标为“演示”，并说明坐标和客流为演示值 | 标签可见；未把演示客流当实时数据验收 |

## 验收边界

- 浏览器预览没有运行后端；天气正在加载、问答返回 HTTP 500 均不能代表真实部署表现。
- 未授权浏览器访问位置、麦克风或摄像头，因此 GPS 拒绝/低精度、真实录音、相机识景、真实供应商 TTS、播放中断及切后台未覆盖。
- 没有连接正式天气、地图/客流服务或数据库，也没有验证真实坐标和客流。
- 复验截图来自当前嵌入式浏览器窗口；本次新增自动检查覆盖目标桌面断点的 class/CSS 规则，但未用真实设备对多种桌面分辨率做逐台采样。
- 本轮仅修复明显影响演示的地图栏宽度；构建体积提示及其他低显著度问题记录为后续性能/兼容性验收项，不在本轮扩展处理。
