# AI 工作台弱网与流式体验 Implementation Plan

**Goal:** 改善聊天文字与语音在弱网、停止和故障下的用户体验，并建立可重复验证的性能基线。

**Architecture:** 保留 Vue、FastAPI 与 fetch POST SSE，统一连接/进展/总时限、完整性和请求代际；共享播放器检查异步解码后的代际。再基于实际依赖和 K01 契约实现可安全复用的后续能力。

**Tech Stack:** Vue 3、Pinia、Vite、Node 原生测试、FastAPI、pytest。

**Spec:** `docs/superpowers/specs/2026-10-28-resilient-ai-stream-design.md`。

## 全局约束

保留现有事件及同源代理；停止后旧回调不修改新轮次；不提交或覆盖已有用户改动。K01 位于另一检出，以其最终实现为准。消息内容和音频不作为默认遥测；不能把心跳当成业务进展。真实终端、供应商和网络结果必须独立记录。

## Review Focus

- EOF 缺少结束事件、部分文本时不应显示成功。
- 心跳正常但业务停滞、调用方主动停止与无数据超时区分。
- 旧轮次抛错/解码完成晚于新轮次，不能停止或覆盖新播放。
- SSE UTF-8、CRLF 分块及最后不完整事件不得损坏数据或伪造完成。
- 重试不能自动重复高成本请求；K01 版本/持久任务不能凭当前旧分支臆造。

## 任务与完成证据

1. SSE 健壮性：在 `frontend/tests` 编写 Node 行为测试，覆盖分帧、无数据/无进展/总时限与取消；实现 `frontend/src/composables/useSSEStream.js`，清理资源并验证。正常帧保持兼容。
2. 聊天状态与播放隔离：先测试真实 Pinia store、共享播放器在部分 EOF、旧请求失败、异步解码迟到和停止后重新请求的行为；更新 `stores/chat.js`、`useAudioPlayer.js` 和所需 UI，保留有效文字，状态符合实际。
3. 可观测性：先测试首字、首次音频数据及实际播放采样区分和不包含文本内容；实现低开销、可关闭的会话内记录，明确不可测场景。评估现有 TTS 队列和分段后优化有依据的问题，保留对照。
4. 跨功能与 K01：核对识景、讲解和 K01 实际恢复接口，修复可安全共享的超时和失败提示；涉及数据模型、鉴权或版本语义时以事实和验收为依据，不覆盖另一个检出。
5. 运行针对性测试、前端生产构建、后端适用测试与仓库地图检查；实测合适的桌面浏览器故障路径；记录设备、网络条件和未覆盖真机/供应商结果，更新地图。

每个行为改动先编写能暴露现有问题的测试，观察失败后修复并回归。根据实验修正计划并记录原因。
