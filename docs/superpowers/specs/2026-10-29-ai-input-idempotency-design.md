# AI 输入接口短期幂等设计

## 目标

弱网重试或重复提交时，ASR 与图片识别的同一逻辑操作只调用一次上游服务，并把完成结果返回给重试请求。

## 方案

- 前端每个逻辑录音/图片识别操作生成随机 `Idempotency-Key`；同一逻辑操作重发时复用该 key，新内容/新操作使用新 key。
- 后端以 endpoint + key 建立短期操作记录，以请求 SHA-256 fingerprint 防止同 key 被不同内容误复用；并发同键同指纹请求共享同一 Future，完成后短期返回相同 JSON 结果。
- 失败结果不缓存，后续同 key 可重试；同 key 不同内容返回 409。
- 缓存限制为进程内、5 分钟 TTL、最多 128 项、结果 JSON 总计不超过 1 MiB；in-flight 任务也计入 128 项上限，满载且没有可淘汰完成项时返回 429。超 1 MiB 的单个结果仍返回调用方但不缓存。协调器不保存输入音频/图片，不跨进程或重启恢复。
- 仅在后端分配的容量许可内执行一次 provider 操作；重复请求在命中时不再占用 provider 容量。
- 请求未提供 key 的旧客户端沿用原行为。前端使用场景均发送 key。

## 边界

- 用户明确发起的新录音/新图片分析是新操作，可以再次计费。
- 此方案针对 ASR 和图片识别，不让同一请求重放聊天 SSE 事件；聊天流保留现有按钮防连点与用户显式重试。聊天跨进程持久幂等与 K01 发布任务恢复需要单独设计。
- 多 worker 部署时各进程缓存不共享；当前部署未提供 Redis/共享缓存配置，不虚构跨 worker 的幂等保证。

## 验收

- 同 key、同请求的并发和完成后重试只执行一次服务调用并得到相同结构结果。
- 同 key、不同内容返回 409，不泄露先前结果；服务失败后重试会重新执行。
- TTL/条目数/总结果字节上限、in-flight 限额、取消 waiter 不取消 provider 和输入不落缓存均有测试。
- 前端每个操作携带键，新图片更换时创建新键；ASR 每次录音创建新键。
- 更新 F01 时准确标注此项是 ASR/视觉进程内覆盖范围，聊天持久幂等和 K01 发布仍开放。
