# 聊天语音版本与重播缓存设计

## 目标

让已保存回答能追溯回答文本版本、生成时的 TTS 音色与关键合成参数；重播优先保持生成时的音色，并对相同回答/合成配置复用短期缓存。

## 方案

- 为聊天日志增加可空 JSON 文本列 `speech_metadata`，旧记录不回填，保持兼容。
- 元数据包含回答 SHA-256 指纹、音色预设、TTS provider、模型/资源 ID、解析后的 voice ID、输出格式、采样率、速率基线和合成 profile 指纹。不保存凭据、原始音频或其他秘密。
- 聊天保存时从当前服务设置及请求音色生成 profile；重播使用历史音色预设，缺少旧元数据时回退请求中的当前音色。
- 重播缓存键由回答指纹和当前合成 profile 共同构成；在进程内使用 TTL + LRU 有界缓存，缓存命中只在相同文本及合成参数下生效。缓存不共享跨进程、不持久化，服务重启即失效。
- 游客语速偏好继续保存在本机。跨设备同步等 W01 的身份/授权设计完成后再纳入；匿名 `session_id` 不作为跨设备身份。

## 不做

- 不缓存聊天首次生成时的流式音频；该链路分句、分块且可能和存档回答文本不同。
- 不持久化音频、不做跨进程缓存，也不在本轮增加身份系统。
- 不回填旧聊天日志的音色或版本猜测。

## 验收

- 新聊天日志写入无秘密的回答指纹与生成 profile；旧数据库通过可逆 Alembic 迁移升级，旧行继续可读取。
- 相同文本/profile 命中重播缓存；修改文本、voice、model、provider、format 或 sample rate 均失效。
- 重播从日志读取原预设；旧数据回退请求预设；跨会话校验仍生效。
- 自动化测试覆盖缓存边界、过期、LRU、参数隔离和重播音色选择；完整后端/前端回归及仓库地图通过。
- 跨设备偏好同步保持待 W01 身份策略完成后评估；供应商和真机验收需现场环境另行执行。
