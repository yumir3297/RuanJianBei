# 知识草稿工作区与发布设计

日期：2026-10-27。状态：用户已在对话中确认设计，本文记录实现依据。
对应仓库：https://github.com/yumir3297/RuanJianBei
静态代码核查基线：540568e231bbda10bfdfdeceaea4041aa681b078；未运行应用。

## 目标与已确认要求

统一批量文件上传、重新导入与单条编辑，让管理员在发布前检查和修正资料，避免游客检索到未审核、过期或已删除内容。

- 保存为草稿；每条知识可以独立编辑、发布。
- 一次上传多个文件，解析结果进入同一个草稿工作区。
- 草稿永久持久保存，刷新、退出、重启后可恢复，不自动过期；管理员可主动丢弃。
- 上传完成到正式发布之间允许修改标题、正文、分类等内容。
- 勾选多条可批量发布；全部准备成功后统一生效。
- 发布失败保留旧版与草稿，显示失败原因并支持重试。
- 发布固定点击时的草稿版本；后续编辑形成后续草稿，不混入正在发布的内容。
- 删除已发布知识立即下架；检索与相关缓存不能继续使用；旧任务或再次导入不能自动恢复。
- PDF 更新绑定已有文档的新版本，不凭文件名覆盖；相同文件重复上传避免重复生成。
- 对比结果区分不变、新增、修改、疑似移除、冲突；缺失章节不得因解析失败而自动删除。
- 重新导入保留已有草稿、人工修改和来源，冲突需人工确认。

## 方案取舍

方案一：逐条版本管理，增量准备切块、向量，以数据库事务切换发布指针；支持把多条切换放入同一事务。推荐方案已被后续设计确认采纳，符合独立编辑与选中批量发布。

方案二：每次修改均重建整库后切换。全库一致性直观，但单条更新成本更高。本次不作为日常发布方式；管理端全量重建仍需避免删除正在使用的集合。

## 用户流程

批量上传／更新文档／单条编辑 → 持久草稿工作区 → 对比、确认冲突、编辑 → 单条或选中批量发布 → 游客使用新版。

草稿、发布状态分开显示：同一条目可以同时具有已发布版本、新草稿和发布任务。发布成功不删除发布期间产生的后续编辑。丢弃草稿不等于下架已发布知识。

## 实现建议（技术决定，非用户另行指定）

- 保持 FastAPI、SQLAlchemy、ChromaDB、Vue 3 与 Element Plus，兼容现有 PostgreSQL 与 SQLite 路径。
- 稳定知识 ID 与不可变修订 ID 分离；文档、文档版本、导入任务、冲突、发布任务持久保存。
- 版本向量提前写入但不可被游客使用；数据库内已发布指针为唯一可见性依据。向量、数据库回退检索、直接读取均执行可见性检查。
- 发布和下架递增数据库知识代次；所有进程的答案、讲解缓存按代次隔离，旧任务不能以新代次写回旧答案。
- 已发布删除采用下架标记和防恢复记录，物理索引清理由可重试任务完成；清理延迟不影响可见性。
- 请求重复提交使用幂等键；编辑使用版本号防止覆盖；任务重启可恢复，不依赖单进程内存任务。
- 首批解析器建议覆盖预处理 JSON 和有文本层 PDF。扫描 PDF 通过独立 OCR 适配器接入；未接入时明确显示需要 OCR，保留原件，不生成空白发布内容。完整 OCR 引擎复用按原路线图另项推进。
- 文件数量、大小、页数和解析时限使用可配置边界，实施时结合现有部署验证；永久保存不代表无限单次上传。

## 边界

本次不更换语言架构，不实现社区或其他路线图功能。文件格式和完整 OCR 支持不能仅凭上传成功宣称完成。
已展示的历史聊天无法撤回；下架保证之后的检索、缓存读取及后续输出不再把该条作为有效知识。流式请求遇下架须停止相关后续生成并提示重试。
永久保存指应用不主动按时间清理，实际持久性仍依赖数据库、原件存储和备份恢复。

## 验收

1. 草稿保存后重启服务并重新登录，内容和来源仍在；游客看不到草稿。
2. 单条发布生效；批量发布中任一准备失败，全部保持旧版。
3. 发布过程中继续编辑、再次发布或删除，不覆盖后续草稿、不复活已删除条目。
4. PDF 同名不同文件、同文件重复、插页、章节更名、部分解析失败均不误覆盖或误删。
5. 人工修改与新文件冲突有对比和选择，未确认冲突不能发布。
6. 删除后在向量未清理、旧内存缓存、数据库回退、讲解缓存中均不可再读取；其他条目正常。
7. 旧同步、全量重建、启动初始化不能绕过新发布规则；现有数据迁移后已发布内容保持可用。
