# W01 游客游览任务与成果基础设计

## 目标与意图

为游客提供不注册账号的游览任务保存与恢复能力，并为 V01 可编辑行程提供稳定的数据归属、版本与成果引用基础。游客在同一浏览器可重新打开已保存游览；服务重启后仍可读取。首版不承诺跨设备找回。

## 范围

- 匿名游客身份通过服务端签发的随机凭据建立；凭据由 HttpOnly Cookie 承载，数据库仅保存摘要。
- 游览任务与聊天 session 分离，保存景区、名称、状态、当前修订和时间戳。
- 行程修订不可变，保存结构化约束、景点顺序、来源与可用的已发布内容版本引用。
- 支持创建、列出、读取、保存新修订、恢复历史修订、软删除、回收站恢复与永久删除。
- 以乐观版本号处理并发编辑；幂等键防止超时重试重复创建任务/修订。
- 游客端增加“我的游览”轻量入口，展示保存状态、列表、继续与删除/恢复操作。

## 非目标

- 账号注册、跨设备同步或身份恢复。
- AI 生成、对话编辑、路线可达性/开放时间校验及开始后的景点进度；这些属于 V01。
- 自动迁移聊天历史、照片、定位数据或访客记忆到游览任务。
- 管理员读取私人游览、运营统计访问私人内容。
- 把游客任务或草稿写入公共知识检索。

## 数据与权限

- 现有 `visitor_id` 是客户端可读写的匿名标识，不作为授权凭据。后端为首次请求建立随机身份凭据，设置 `HttpOnly; SameSite=Lax; Secure(HTTPS)` Cookie；仅保存凭据 SHA-256 摘要。Cookie 有效期 365 天，用户清除 Cookie 后不能找回旧数据。
- 所有游览读写都由 Cookie 解析出的身份进行所有权过滤。任务 ID 本身不授予访问权；未登录匿名身份不可访问其他游客任务。
- 所有写请求要求 `Origin` 与请求 Host 同源，并要求 `X-CSRF-Token` 与同源可读 `tour_csrf` Cookie 相同；该 token 包含由服务端密钥签名的身份绑定值。身份 Cookie 为 HttpOnly，CSRF Cookie 设 `SameSite=Lax; Path=/api` 且不设 HttpOnly；初始化接口在 JSON 中返回 token，前端保存在内存并放入写请求头。API 部署使用现有同源 `/api` 代理；跨域部署需通过可信配置明确允许来源。
- 匿名身份/游览任务/修订使用独立 SQLAlchemy 模型和 Alembic 迁移。游客个人数据不复用 `VisitorMemory`，不进入管理员查询或 RAG。
- 游览任务包含 `site_id`，首版从当前服务端单景区配置取得；不可由游客任意切换到未配置景区。

## 任务与修订行为

- 任务 ID、修订 ID、幂等键均使用 UUID。任务初始状态为 `draft`，首版状态限于 `draft`、`active`、`completed`；本功能只创建 `draft`，其他状态供 V01 使用。
- 修订是完整快照，字段包含同行人、可用时长、兴趣、必去/排除景点、步行偏好、按序景点条目、来源说明、发布内容版本映射及创建时间。首版允许空行程；不推断景点稳定 ID，未知景点以未解析状态保存原始名称。
- 每次保存带 `expected_version`。匹配当前版本时事务内创建下一修订并切换当前版本；不匹配返回 `409` 和当前版本摘要，不覆盖本地编辑。
- 同一所有者、同一端点和同一幂等键的重试返回原响应；同一键搭配不同请求体返回 `409`。幂等记录持久化 7 天并在过期后清理，不保存敏感凭据。
- 删除采用软删除，默认回收期 30 天；恢复仅限回收期内。永久删除清除任务、修订与幂等关联数据；删除操作需显式确认。
- 历史修订恢复会新增修订并递增版本，不改写历史记录。

## 界面与失败处理

- 在现有路线工具加入“我的游览”入口，不重构游客主舞台。
- 提供新建、任务列表、继续编辑、保存状态、版本冲突提示、回收站恢复和永久删除确认。
- 网络失败时保留当前表单/草稿在内存并允许重试；不将其标记为已保存。刷新后的服务端恢复只保证已成功保存的修订。
- Cookie 不可用（如浏览器禁用）时说明保存不可用，保留现有路线与聊天体验。

## 验收标准

1. 游客 A 创建并保存任务后，刷新、重新打开同一浏览器、重启服务后都能恢复当前修订。
2. 游客 B 不能用任务 ID 读取、修改、删除或恢复 A 的任务；管理员 token 也不扩大访问权。
3. 两个标签页基于同一版本修改时，一个成功，另一个收到 `409` 且服务端内容不被静默覆盖。
4. 幂等重试不会生成重复任务或修订；同键异内容返回 `409`。
5. 删除后任务退出普通列表；30 天内可恢复；永久删除后不可恢复。
6. 恢复旧修订创建新版本，原修订内容保持不变。
7. 数据库升级可在当前 PostgreSQL 迁移链运行，并通过隔离 SQLite 覆盖服务层自动化测试。
8. 既有聊天、推荐、重播与管理员认证回归通过；代码地图同步记录新增模型、接口、页面与验证入口。

## 实施决策

- 持久化采用 SQLAlchemy + Alembic，与现有应用保持一致。
- 首版只以同源 Cookie 访问为目标；本地 Vite 代理及生产同源反向代理作为支持部署方式。
- 删除回收期按确认方案采用 30 天。
- 幂等响应记录保留 7 天，签名 CSRF token 使用现有服务端签名密钥并绑定匿名身份。
- 任务成果引用先提供数据库关联结构与 API 表达，不在 W01 内生成总结或分享图。
