# 非 WAV 音频时长校验设计

## 现状与目标

ASR 上传已有请求体字节上限，WAV 可从头部读取并校验时长；压缩音频只受字节数限制，无法阻止小体积长音频触发高成本识别。游客前端录音器当前固定生成 WAV，其他 API 客户端仍可上传 MP3、M4A、WebM 等格式。

## 方案

- 对真实 ASR provider 的非 WAV 请求，在取得现有 ASR 容量许可后，用系统 `ffprobe` 探测上传文件的短暂私有临时副本。MP3 流输入不能可靠提供时长，临时文件使 MP3、M4A 等可 seek 容器都能正确探测。
- 临时文件使用系统私有临时目录和随机文件名，正常、错误、超时及取消路径均删除；`ffprobe` 仅允许 `file` 协议，限制 probe/analyze 时间和最大分配，stderr 丢弃，不记录路径或音频内容。
- `ffprobe` 命令路径和探测超时可配置。
- JSON 输出必须包含有效正时长及至少一个 audio stream；格式无法探测、没有音轨或进程超时均在调用 ASR provider 前返回清晰 400/503。超过 `asr_max_audio_seconds` 返回 413。
- WAV 继续走既有内置校验；stub 模式兼容任意测试/占位内容，不要求安装 ffprobe。
- ffprobe 不随 Python requirements 安装；部署真实 ASR 且接收非 WAV 时需预装 FFmpeg 并配置可执行路径。现有前端继续只发 WAV，因此无需依赖外部探测器。

## 验收与限制

- 覆盖合法时长、过长、无效/无音轨、探测器不存在、超时、stdout 异常、临时文件清理及 WAV/stub 兼容。
- route 集成证明异常在 provider 调用前拦截，成功探测遵守当前秒数上限。
- 探测通过 subprocess 超时、上传字节上限和系统临时目录限制；该检查不等于完整解码验证，不承诺对每个容器/损坏尾部字节都完整解码。系统突然断电时可能留下 OS 临时文件，操作系统通常会按其临时目录清理策略回收。
