# 风景背景与数字人：功能面板重构

## 问题与方向

用户反馈无遮罩版本视觉零碎。当前实际问题是白色按钮分散在复杂照片上，文字依赖粗阴影，导览、讲解与语音操作没有统一的视觉层级。本次保留可替换的整页风景照片和中央数字人，把辅助功能收进一致的深色面板，以人物和语音操作作为主要视觉焦点。

## 查阅来源

| 来源 | 可确认的原则 | 本项目采用方式 |
| --- | --- | --- |
| [Babylon.js Editor 布局](https://editor.babylonjs.com/documentation/basics/composing-scene) | 左侧场景选择、中央预览、右侧属性设置 | 保留中央人物及独立侧栏，展开功能不挤压人物 |
| [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials) | 通过材质区分操作与内容；使用透明材质时同时处理可读性；避免滥用玻璃效果 | 为功能提供稳定的深色承载面，照片仍完整显示 |
| [Microsoft Acrylic](https://learn.microsoft.com/en-us/windows/apps/design/style/acrylic) | 透明、模糊与色调共同建立层级；避免多个材质紧贴或叠加；兼顾对比度、性能与透明效果关闭后的降级 | 面板之间留出空间；展开阅读使用实色；提供无模糊与减少透明效果的回退 |
| [NVIDIA 数字人参考工作流](https://github.com/NVIDIA-AI-Blueprints/digital-human) | 提供面向企业服务的三维数字人交互工作流 | 用于了解类似产品定位；该仓库没有足够的界面细节，未把它当作三栏布局的证据 |

以上是对来源原则的适配。网页里的 CSS 不是 Apple Liquid Glass 或 Windows Acrylic 的原生实现。

## 修改

- 整页风景没有白色渐变遮罩，背景替换接口保持原样。
- 两侧导览与讲解使用同一面板配色、边框、圆角与间距。工具按钮、常用提问改为面板内列表，去掉散落的白色块。
- 拍照、语音与键盘操作合并在底部操作面板中。语音主按钮使用浅色、其他操作使用低强调样式。
- 删除照片上的粗文字阴影；名称放在紧凑标签中，状态文字仅保留轻微阴影。
- 图片旁的标题与正文使用统一明暗层级。阅读面板、筛选输入框、按钮悬停与禁用状态适配深色。
- 手机使用底部统一导航与原生 dialog；短横屏把人物与操作区分别放置。背景图片继续可替换。
- 只有独立的功能承载面启用背景模糊。浏览器不支持模糊时使用更实的颜色，系统要求减少透明效果时使用实色并关闭模糊。

本轮修改集中于 `guide-page.css`、`guide-tools.css`。样式曾拆为第二个外部 scoped 文件，开发预览解析了错误的 Windows 路径；已合回原样式文件，保留一个外部样式入口。

## 实际查看

浏览器查看桌面 1440×900 默认与双侧面板状态、手机 390×844 的默认与键盘输入状态、小屏 320×568、横屏 844×390。检查过的手机和横屏页面无横向溢出，横屏只有一个人物画布。当前系统的 `prefers-reduced-transparency: reduce` 为真，所以实际截图展示实色回退；没有据此声称已视觉检查半透明分支。没有录音、上传背景或执行自动化测试。
