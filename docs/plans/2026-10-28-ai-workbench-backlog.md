# 双端 AI 工作台待开发清单

更新日期：2026-10-29。核对代码基线：`672a104`，并记录其后当前工作副本中的未提交实现。本文是产品待开发清单，不是已实施架构或逐文件实施计划。

产品方向：游客智能伴游与景区 AI 运营工作台同时建设，围绕共同的已发布景区内容形成闭环。阶段顺序以[路线图](2026-10-27-feature-roadmap.md)为准；当前实现以[功能地图](../REPO_MAP.md)与源码为准。

- 下述阶段和优先级是本轮整理后的建议安排，具体接口、布局和算法仍需对应功能设计。

- 赛题原文与评分细则尚未归档，赛题合规结论待核对原文；不把其他届次公告当成本届验收标准。

## 2. 双端共同主线

运营：导入资料 → 人工修正草稿 → 生成及预览讲解内容 → 发布 → 验证游客可用。

游客：描述需求 → 生成行程草稿 → 人工或对话修改 → 确认并开始游览 → 识景与讲解 → 保存游览记录及总结。

反馈：游客问题与反馈 → 运营待办 → 核查资料并补充内容 → 发布新版 → 验证原问题 → 关闭待办。

两端共享景点稳定 ID、知识来源、已发布内容及版本；游客私人行程、照片与运营草稿分别鉴权。运营统计不自动赋予查看全部游客私人资料的权限。

## 3. 首阶段：基础与运营知识闭环

### K01 知识草稿、版本与发布｜设计已确认／待实施

沿用[已确认设计](../superpowers/specs/2026-10-27-knowledge-workspace-design.md)。该设计在本轮从项目外层文档等内容归档至仓库，未重新定义原有约定。

- [ ] 统一单条编辑、批量上传、重新导入，保存永久草稿及来源。
- [ ] 单条与选中批量发布；固定发布时修订，批量准备失败保持旧版。
- [ ] 版本化切块与向量、发布可见性检查、缓存代次；覆盖 FAQ、回退检索与地图讲解。
- [ ] 发布中编辑不丢后续草稿；下架立即不可读，旧任务不复活内容。
- [ ] 导入冲突对比、人工修改保留、同文件去重、同名文件不误覆盖。
- [ ] 持久发布任务、幂等、失败重试、服务重启恢复。

验收：上传资料、修改草稿、发布后问答引用新版；未发布内容不可检索；批量失败保留旧版；下架后旧缓存与旧任务均不能继续提供失效知识。

依赖：现有知识、检索与数据库；首批采用已确认设计建议的预处理 JSON 与文本层 PDF，完整 OCR 由 K02 补齐。

### F01 异常、弱网与性能基线｜进行中；流式恢复、播放隔离和部分输入保护已实现

- [x] 普通 HTTP 请求沿用 10 秒客户端超时；流式请求增加连接、无数据、无业务进展和总时限，处理提前结束、部分结果与失败标识。SSE 心跳不会重置业务进展时限。
- [x] 停止、切换、新请求与旧响应隔离；播放器拒绝迟到的解码和语音回调。聊天重试由用户触发，不自动重复高成本请求。
- [x] 聊天与地图讲解共用播放器时按播放会话隔离；新来源接管会停止旧来源，旧来源不能再入队或停止新来源。地图工具隐藏时清理自己的讲解、定位与巡游任务；当前仅完成源码与自动化覆盖，真机生命周期仍待验收。
- [x] ASR 与图片识别支持短期请求幂等：前端每个操作发送随机键；后端按接口、键和请求指纹合并并发请求、缓存短期结果，键复用不同内容返回 409。限制为进程内 5 分钟、最多 128 项、结果 JSON 最多 1 MiB；不保存上传原文，不跨 worker 或重启保证，旧客户端可不带键。
- [ ] 扩展到所有高成本操作并覆盖持久/跨进程重复保护。聊天 SSE 与 K01 发布恢复仍需独立设计或接入；K01 发布恢复补丁尚未应用到其正在开发的检出。
- [x] 图片上传校验格式、大小、声明尺寸/像素上限并给出可理解反馈；WAV 校验实际格式、大小及时长。
- [x] 对真实 ASR provider 的非 WAV 输入用可配置 `ffprobe` 在容量许可内探测时长，超过限制或内容无法探测时在上游调用前拒绝；需要部署环境预装 FFmpeg，游客录音器当前仍只发 WAV。
- [ ] 上传内容完整解码校验；时长探测只确认可识别的音轨与时长，不代表解码并验证每个媒体帧或文件尾。
- [x] ASR、TTS、视觉与聊天失败时保留可用文字/结果，并提供取消、失败提示或手动重试入口。
- [x] 核对管理 API 已要求 Bearer token，但默认签名密钥/管理员密码可预测；`APP_ENV=production` 现 fail-fast 要求非默认、足够长的管理员密码和 token secret。游客端接口仍为公开访问。
- [ ] 为公开游客高成本接口建立有可信客户端身份的持续速率限制；现有容量限制仅按进程控制同时任务数，多 worker/时间窗口防刷交给网关或共享限流器，需先确定可信代理配置。
- [x] 记录会话内首段文字/音频接收时间、音频排程时间、完整回答耗时和结果状态；样本只保留在内存，不含问题或答案。
- [ ] 测量首字可见、首声可闻、首屏、数字人、地图加载、失败率、真实并发及资源消耗；现有音频排程指标不等同于扬声器实际出声。

验收：断流、长期无数据和用户停止的自动化行为已覆盖；有效内容保留。完整验收仍需证明断网恢复、重复写入保护，并记录实际设备、网络、版本、时延、失败率和资源测量。当前测试结果及限制见[验收记录](../superpowers/plans/2026-10-28-ai-stream-validation.md)；K01 发布恢复补丁见[集成补丁](../superpowers/plans/2026-10-28-k01-stream-integration.patch)。真实手机弱网和供应商端到端对照尚未执行。

## 4. 第二阶段：游客任务与行程闭环

### W01 工作区身份、归属与成果基础｜待设计，新增

- [ ] 明确游客游览任务、运营工作任务和普通聊天会话的关系；会话 ID 不代替任务 ID。
- [ ] 最小对象覆盖：游览任务、行程及修订、任务执行记录、成果引用；先支撑首个行程闭环。
- [ ] 记录景区、所有者、来源与内容版本；游客行程与后台内容权限分开。
- [ ] 持久保存、读取、编辑冲突处理、主动删除与恢复入口。
- [ ] 首版匿名游客可在同一浏览器恢复；跨设备恢复需另行设计身份机制，不凭本地标识承诺支持。

验收：刷新、重新打开浏览器与服务重启后可恢复已保存任务；其他游客不可读取；草稿不流入公共检索；并发编辑不静默覆盖。

### V01 可编辑行程与连续对话修改｜待设计，新增

- [ ] 结构化采集同行人、时长、兴趣、必去与排除景点、步行偏好；未知约束明确保留。
- [ ] 预设路线作为初始模板，生成引用景点 ID 的行程草稿，而非只返回路线文字。
- [ ] 手动增删、排序与对话修改操作同一份行程，修改前后可比较、撤销并保存版本。
- [ ] 校验时间安排、景点可用性和路线约束；无开放时间或路网数据时说明估算与未知，不虚构可达性。
- [ ] 用户确认后开始游览，记录待游、当前、已完成和跳过景点；恢复后继续。
- [ ] 信息不足时询问关键条件，约束不可满足时给出可解释的调整建议。

验收：“老人和孩子、三小时、少走路”生成草稿；“去掉某景点、多留休息时间”修改原行程并保留约束；人工编辑后 AI 不擅自覆盖；关闭重开能继续。

依赖：W01、F01、稳定景点 ID 与已发布内容；首轮不依赖真实客流、持续 GPS 或复杂 Agent 框架。

### W02 工具执行与任务恢复｜待设计，新增

2026-10-29：完成[实现调研](../research/2026-10-29-w02-durable-execution-research.md)，用户选择“现有数据库 + 小型执行器”；[具体设计](../superpowers/specs/2026-10-29-w02-durable-execution-design.md)待审阅，业务尚未实现。[卖点与证据规划](../selling-points/w02-continuous-tour-recovery.md)仅描述待验收目标。

- [ ] 为检索、路线调整、识景、讲解生成、导入与发布定义输入输出与能力边界，复用已有服务。
- [ ] 区分短请求状态、可恢复后台作业和整个业务任务状态；游客任务与运营发布各自授权。
- [ ] 展示必要的步骤、结果、错误与重试，不将模型内部推理当作执行证据。
- [ ] 长任务持久记录阶段、幂等键及重试边界；重启可恢复，不以浏览器连接或单进程内存为唯一依据。
- [ ] 并行修改、取消和旧任务返回时校验目标版本；自动生成只写草稿，发布仍沿用人工操作。
- [ ] 先以确定流程完成闭环，模型用于意图与内容处理；不将多智能体作为交付前提。

验收：失败能定位到实际步骤并重试；同请求不重复创建成果；取消或重试不会让旧结果覆盖新版；中断后恢复有实际持久数据支持。

### R01 前后端职责重构｜待设计，新增

- [ ] 游客端拆分舞台与数字人、输入、播放、工具装配和任务编排；聊天状态与行程、成果状态分开。
- [ ] 地图、路线、识景通过稳定对象 ID 与统一动作协作，减少以自然语言字符串传递实体关系。
- [ ] 运营端按导入、修订、预览、发布和待办组织工作，复用现有页面与组件。
- [ ] 后端保持 API 校验与编排、服务层业务、repository 持久化；抽取任务执行与成果版本职责。
- [ ] 新增流事件同步核对服务端、解析器与 store；保留停止隔离、播放器互斥和旧入口兼容。
- [ ] 桌面便于编辑与对照，手机采用单任务操作及逐步展开；具体布局另作设计。

验收：旧聊天、语音与数字人行为回归；路线、地图、识景引用同一当前行程；展开工具不重挂载数字人；性能提升必须有同条件测量。

边界：这是现有 Vue/FastAPI 内部职责调整。更换语言、框架或拆微服务仍暂缓。

## 5. 第三阶段：识景、讲解与成果生产

### V02 拍照识景并关联游览｜待设计，已有识别到问答链路

- [ ] 方向与尺寸处理、压缩、上传校验、候选与低把握确认、失败重试。
- [ ] 区分图像线索与官方事实，最终讲解引用已发布知识。
- [ ] 确认景点后可加入当前行程、查看讲解并保存识景记录，避免重复录入。

验收：地标、指示牌、模糊和非景区图片固定样本评测；歧义不当作确定事实；手机拍照、相册与弱网可恢复。

### V03 统一播放、语速与重播｜部分实施：聊天/地图播放隔离、游客语速偏好与历史答案重播

- [x] 聊天与地图讲解播放互斥、按来源停止；播放会话替换、过期入队与旧来源停止已有自动化覆盖。
- [x] 当前会话中已保存的回答可重播：按 `chat_log_id + session_id` 读取原答案并调用 TTS 重新合成，不重新调用问答模型；TTS 未配置时允许浏览器朗读。每次重播可能产生一次上游 TTS 调用；音频不落库。
- [x] 普通音频、流式 PCM、浏览器朗读统一由前端播放层调速；传给后端的 `tts_rate` 保持 100，避免服务端将来消费该字段后重复变速。
- [x] 游客语速偏好在当前浏览器本地保存，聊天、地图讲解与欢迎语共用；播放进度按源内容时间报告，字幕和嘴型时间线不随速度倍率漂移。
- [x] 聊天记录关联答案 SHA-256 内容版本、生成时音色预设及 provider/model/voice/格式/采样率 profile；历史重播优先原音色，缓存键覆盖答案与完整合成 profile。TTS 音频使用进程内 TTL/LRU 缓存（30 分钟、最多 128 条、编码音频总计 16 MiB），不跨进程/重启；跨设备语速同步等 W01 身份与授权设计后再评估，当前明确只保存在本机。
- [ ] 关联当前景点与行程进度；评估跨页面来源恢复规则和完整播放场景。

验收：会话互斥、本地语速偏好、历史答案重播的数据归属/迟到响应、语音 profile 隔离与进程内缓存均有自动化覆盖；支持路径调速后字幕和嘴型仍需浏览器/真机实测；行程关联、页面不可见及来源恢复场景继续验收。

### K02 扩展解析与 OCR｜待设计

- [ ] 定位已有 OCR 工具并核对集成方式；明确首批扩展格式、页数、大小与时限。
- [ ] 长任务进度、失败原因、取消及重试；扫描件与文本 PDF 区分，保留原件、页码和段落来源。
- [ ] 解析进入 K01 草稿与冲突流程；需要 OCR 但未配置时明确提示，不发布空内容。

验收：损坏、加密、扫描、多文件部分失败与重复上传不误发布或覆盖；引用可追溯原文位置。

### O01 讲解内容生产与发布预览｜待设计，新增

- [ ] 基于已发布知识或管理员有权访问的草稿生成讲解稿，保留证据和来源版本。
- [ ] 支持儿童、常规、深度讲解草稿及人工编辑；事实不随风格改写。
- [ ] 在目标数字人、音色与手机/桌面场景预览；预览内容与游客正式内容隔离。
- [ ] 复用版本、任务和发布机制，校验引用及可用音频，失败保留旧版。

验收：运营生成、修改、试听并发布；游客获得对应版本；来源变更能提示复核；草稿仅在授权预览中使用。

### W03 成果库、游览总结与图片导出｜待设计，扩展原总结功能

- [ ] 在 W01 最小存储上补齐成果列表、编辑、历史版本与来源；覆盖行程、讲解稿、识景记录和游览总结。
- [ ] 游客选择实际游览内容生成总结草稿，可修改并保存，再导出分享图。
- [ ] 导出处理长文本、字体、素材跨域及加载失败；不把聊天全文或未完成景点自动当成游览事实。
- [ ] 照片与位置是否纳入由用户选择；保存与主动分享分开。

验收：同一成果能继续编辑和恢复；导出图片与选定版本一致；手机保存、长文本、缺素材可用。

## 6. 第四阶段：双端反馈闭环与现场增强

### O02 从知识盲区到运营待办｜待设计，已有盲区追踪

- [ ] 从未答好问题、重复反馈与内容过期形成可追踪待办，去重并关联景点和证据。
- [ ] 待办包含处理状态、权限、处理说明与关联修订；角色分派按首版实际人员需求设计。
- [ ] 核查 → 补充知识或讲解 → 草稿审核 → 发布 → 原问题回归 → 关闭；仅发布成功不自动判定问题解决。
- [ ] 看板展示真实待处理、已处理和验证结果，可跳转处理；不虚构收益指标。

验收：从游客问题创建待办，经发布和原问题复测关闭，过程可追溯；运营只访问处理所需信息。

### V04 真实定位、客流与行程调整｜待设计，真实客流待数据源

- [ ] 修复并真机验证定位字段、坐标系、精度、时间与景点匹配；明确真实、模拟、过期和拒绝状态。
- [ ] 验证进入、离开、重复靠近、播放忙时排队及自动讲解控制。
- [ ] 接入带区域、更新时间、来源与有效性的真实客流；不可用时回退预设建议并标记。
- [ ] 天气、位置与客流变化给出行程修改草稿，解释影响并由用户确认；已完成景点保持记录。

验收：真实位置与模拟数据可区分；过期客流不伪装实时；调整满足已知约束并作用于原行程；没有数据源时不宣称避拥挤已实现。

### V05 现场求助｜待设计

- [ ] 展示核实的景区联系方式；获取带时间与精度的真实位置，失败可手动描述。
- [ ] 支持拨号、复制或主动分享位置；不使用模拟坐标。
- [ ] 后台接警作为单独扩展：先确定接收人员、送达、受理、超时与演练流程。

验收：定位拒绝或失败仍能求助；拨号/分享与后台受理分开表达，不能将点击按钮显示为已获救援。

## 7. 第五阶段：扩展体验与容量

### E01 照片美化｜待设计，原范围为暂定理解

- [ ] 确认裁剪、旋转、亮度、滤镜、景区相框与文案范围；挂接游览记录和成果导出。
- [ ] 优先评估浏览器内处理，保存与主动上传分开；评估大图内存、失败占位与手机保存。

验收：原图不被无提示覆盖，编辑可预览、保存；不作为首轮工作台闭环的依赖。

### E02 社区小贴士｜待设计

- [ ] 先做景点下文字/图片、审核、展示、反馈与举报，再讨论完整社区。
- [ ] 明确身份、权限、存储和隐藏规则；官方内容与游客内容分开，入知识库须另行审核发布。

验收：投稿到审核展示闭环、举报可处理、隐藏后不可继续公开读取；未审核内容不进入官方 RAG。

### E03 情绪与需求响应评估｜待设计，已有分析规则

- [ ] 明确采集范围、保存与有效期，建立否定、反问、噪声等样本与纠正机制。
- [ ] 评估现有规则，再决定模型；规则分值与校准概率区分，求助保留独立入口。

验收：固定样本和实际反馈验证策略效果，不凭展示情绪标签宣称有效。

### E04 容量、成本与离线深化｜待设计，依赖基线

- [ ] 固定负载评测首字、首音频、成功率、CPU、内存与上游调用消耗；根据瓶颈选择连接复用、缓存、限流、队列或任务隔离。
- [ ] 明确服务器、并发目标与供应商配额，不预先承诺容量。
- [ ] 明确离线外壳、主动下载讲解、基础资料、版本与清理；离线地图单独核对来源及方案。

验收：同条件前后对比；断网只展示实际缓存能力；容量结论绑定硬件、版本与负载。
