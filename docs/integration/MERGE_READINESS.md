# 总合并前审示结论

本文档记录本地统一后的合并边界。它服务于代码审示和决策，不代表已经提交、合并或上线。

## 可以进入统一主线的部分

- 游客端与管理端的独立入口、构建产物、认证边界和 API 代理规则。
- 共享游客运行时状态：安全暂停、定位、播放完成记录、行程上下文和已发布目录摘要。
- K01 知识草稿、稳定景点编号、审核发布、版本可见性和来源追踪。
- CASS 情境决策与安全暂停控制；默认保持配置开关，真实预警源未接入前不自动宣称恢复。
- 游览行程 V2、提案预览、用户确认后保存、幂等重放和模拟来源标识。
- Trae 离线陪游的游客端缓存、断网入口、地图/求助资料、恢复提示和版本检查。
- 本地统一验收入口及对应文档、代码映射和验收台账。

## 必须保留但暂不作为生产能力启用

- `demo_synthetic` 行程 provider：只接受本机 HTTP，限 development/test，界面明确标记固定演示规则。
- `simple-dev-embedder`：只在显式设置模型名时启用固定哈希向量，不能用于真实问答质量结论。
- GuideLoop：保留管理端试验、来源复核和 K01 版本绑定；游客端仅在 development/test 开关下按服务端景点范围读取已审核且确认的绑定版本，生产仍关闭。
- GuideMatch 候选权重：用户已确认比赛阶段使用；已在本地开发/测试 FAQ 路径接入并在统一演示显式启用，保留原始文件、哈希和训练记录。生产未启用，独立真实游客评测与结构化字段贯通仍待完成。
- 所有虚构景点、stub 音频、测试联系人、Playwright 模拟断网和临时数据库：只能作为验收夹具，不进入运营数据。

## 合并前应清除或隔离的内容

- 临时 SQLite/Chroma、`output/`、浏览器证据截图、日志和临时服务配置。
- `.env`、管理员密码、API key、模型缓存和本机绝对路径。
- 未确认来源的景区资料、GuideMatch 训练产物和外部 symlink 目标；它们继续放在来源快照或私有归档中。
- 未经审示的跨来源改动；当前工作区有大量未提交/未跟踪文件，必须按来源清单选择性纳入，不能整体 `reset` 或清理。

## 需要最终确认的事项

1. **比赛演示使用哪类资料**：继续使用明确标记的合成资料，还是提供已获许可的真实景区资料做本地验收？这决定 A4/A5 的真实资料门槛。
2. **真实模型是否进入比赛版本**：如果进入，需要提供模型目录、供应商凭据和可接受的回答/延迟标准；否则比赛版本固定使用演示 provider，并在演示词中说明边界。
3. **CASS 默认开关**：比赛演示是否默认开启 CASS；真实预警源未验收前只能使用模拟场景，不能把模拟恢复当作现场接警恢复。
4. **离线发布目标**：先验收本机 Chrome，还是必须补指定 Android/iOS/微信 WebView；后者需要确定设备和发布代理。
5. **数据库目标**：最终本地/比赛环境是否统一 PostgreSQL，还是允许 SQLite 仅用于演示；两者的锁和并发证据不能互相替代。
6. **GuideMatch 取舍**：用户已确认比赛阶段使用，已接入本地开发/测试问答路径；生产使用须另行验收。
7. **生产放量门槛**：服务器、域名、TLS、备份 RPO/RTO、并发 SLO 和回滚窗口尚未给定，因此生产放量结论应保持“暂缓”。

## 建议默认决策（可直接回复“全部采用”或逐项修改）

| 项目 | 建议默认值 | 影响 |
|---|---|---|
| 比赛资料 | 明确标注的合成资料 | 保持本地演示可重复，不虚构真实景区事实 |
| 比赛模型 | 使用本地演示 provider；真实模型另做验收 | 不把未测模型质量带入比赛闭环 |
| CASS | 默认关闭，演示时显式开启模拟场景 | 避免把模拟预警当作现场接警 |
| 离线陪游 | 先验收本机 Chrome，再按实际设备补测 | 不把桌面浏览器结果概括为真机兼容 |
| 比赛数据库 | 本地演示允许 SQLite；正式候选统一 PostgreSQL | 明确 SQLite 与 PostgreSQL 锁/并发证据边界 |
| GuideMatch | 用户已确认比赛阶段使用，统一演示显式启用 | 本地 FAQ 门控已接入；生产及真实游客评测待完成 |
| 生产放量 | 暂缓，等待服务器和运营指标确认 | 当前只进入代码审示和目标机准备阶段 |

## 当前结论

本地合成比赛演示已经形成可重复闭环，适合进入最终代码审示。真实模型、真实资料、真机、生产数据库和生产部署仍然是独立验收阶段，不能因本地脚本通过而自动合并为上线版本。
