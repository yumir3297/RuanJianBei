## 范围和开关

代码来源于 `feat/guideloop-pilot` 工作区的未提交试验成果。当前仅限 `APP_ENV=development|test` 且 `GUIDE_LOOP_PILOT_ENABLED=true`。管理端 Vite 开发环境另需 `VITE_GUIDE_LOOP_PILOT=1`，在知识盲区页显示试验面板；生产构建不显示入口。试验默认关闭，合成案例不代表真实运营事实。

`backend/app/api/guide_loop.py` 的观察、草稿、验证、发布、复测和确认接口均要求管理员 token。`frontend/src/api/guideLoop.js` 的管理操作使用 `adminHttp`；复测使用 `/api/admin/guide-loop/replay`，服务端校验管理员、试验开关、上下文及文本模式，再调用现有聊天流。网关策略只允许管理站访问这些接口，游客站不暴露管理 API。游客不能提交管理复测上下文；受控游客路径由上节所述的服务端景点范围触发。

发布要求人工来源复核声明，复测返回的 check ID 可供管理员确认；来源声明不是事实自动认证。原试点仍有两景点特定规则和模拟撤回说明，需要在接入真实景区前重新设计。GuideLoop 的版本发布与现有 K01 知识发布尚未统一，跨流程的一致性、实时运营、多 worker 并发、真实模型和浏览器端到端均未验收。

2026-11-13：游客聊天接口拒绝携带 `guide_loop` 的请求，即使开发环境打开试验开关也返回 403；管理员认证复测仍可进入试验路径。这是 K01 版本绑定完成前的隔离措施。验收标准：游客构造试验上下文不能获取试验答案；管理员认证且开关启用时仍可复测；K01 绑定和撤回一致性完成前不得开放游客入口。隔离不解决管理员复测中试验答案可能过期的问题，不能将复测内容视为当前 K01 事实。

本次相关后端测试 30 项通过，覆盖游客拒绝、管理员鉴权和复测。未验证 K01 更新或下架后的试验版本一致性。

2026-11-13（续）：草稿可成对指定 K01 条目 ID 与版本 ID；发布时检查其为当前已发布版本，读取时再次检查。换版、下架或不完整引用会拒绝旧答案并阻止该匹配回落至旧 FAQ。旧记录保留为空引用，仅限管理员试验复测；不会自动推断来源。来源支持回答的事实仍需人工核验，引用有效不等于事实正确。该功能尚未覆盖并发发布事务隔离、真实数据库、管理界面选择知识版本或游客正式接入；试验入口仍受上面的隔离约束。

2026-11-13（再续）：管理试验面板可从管理知识列表选择当前发布版本；仅显示条目 ID、发布版本 ID 和是否存在草稿，不把可能来自草稿的标题当作已发布标题。刷新后若所选版本已变更或下架则警示；列表请求失败清空候选并提示重试，发布时仍由后端再次校验。前端单元测试覆盖筛选、绑定及变更检测；实际浏览器选择并发布的完整流程尚待验收。

2026-11-13（浏览器复测）：在新建隔离 SQLite、独立 Chroma、本地 BGE embedding、stub LLM/TTS 和重排降级条件下，用本机 Chrome 完成虚构 K01 发布、管理端选择版本、保存草稿、技术验证、模拟来源确认、发布和 SSE 复测；K01 下架后刷新列表出现版本失效提示，复测拒绝旧回答。脚本为 `frontend/tests/e2e/guide-loop-binding-smoke.mjs`，会写入和下架合成数据，只能用于全新隔离演示库并要求显式确认。此结果不覆盖真实来源、PostgreSQL、并发发布或游客正式路径。
