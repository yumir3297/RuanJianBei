# 连续导览：已保存行程上下文

目标是让游客在当前景点请求情境讲解时，能够自然预告已保存行程的下一站，同时保留 K01 发布知识和服务端行程进度为权威来源。

2026-11-13：`GuideContextStatus` 从共享的当前行程及情境目录派生下一站提示。仅在 V2 行程进度处于 active、当前 stop 与选中景点及发布版本一致、下一个 pending stop 是景点且其版本与已加载目录唯一匹配时生成；休息点、目录重复、下架/版本不匹配或缺少进度时不生成。进度同步失败时 ChatView 不传行程上下文。提示只请求在资料支持时预告，不声称景点存在特定关系、游客已到访或自动更新进度。

这是从原 `narration-policy` 快照中跨站回顾/预告的思路移植到现有 K01 和行程数据，不加载其独立试点事实库，也未实现其事实级已听去重。目录是页面当前加载的快照，后续发布变化需要重新获取目录；最终问答仍由现有知识发布可见性规则控制。当前尚无真实模型质量、完整游客浏览器链路或并发变更验收。

2026-11-13（目录复核）：游客点击生成讲解时重新读取服务端目录并比较景区和目录摘要；变化则清除旧决策、提示重新评估，网络失败则不发起讲解。等待时行程或情境变化、停止、组件卸载或安全事件会使旧核对失效；判断决策是否过期使用当前时间。该检查不是与后续问答的原子事务，目录检查后仍可能发生发布变化，最终知识检索与版本屏障仍须负责可见性；真实并发场景未验收。

验收条件：匹配的当前/下一景点可产生预告请求；不同版本、未开始/结束、休息点、重复目录项和同步失败不产生提示；不改变行程、进度或已听记录；问答不能把提示本身当作事实依据。自动测试覆盖前述派生条件；真实模型和跨组件端到端仍需验证。

2026-11-13（浏览器跨组件）：本机 Chrome 使用拦截的合成行程、进度、目录和 SSE 回答，打开已保存行程并生成情境讲解；目录摘要变化时旧请求被阻止，重新评估后问答请求包含下一待游览景点及不臆造关系提示。脚本为 `frontend/tests/e2e/guide-next-stop-smoke.mjs`；未验证真实 API 数据、真实模型回答、目录并发事务或真实设备。
