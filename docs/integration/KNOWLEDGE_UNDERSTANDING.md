# 知识理解整合记录

2026-11-13（景点编号）：管理端手动创建或编辑景点知识时可填写稳定 `attraction_id`，用于发布后进入游客行程和情境目录；编辑时保留其他元数据，格式无效时拒绝提交。编号可选，当前没有服务端唯一性约束或不可变约束，需由管理员核对且避免发布后修改；重复编号、历史映射及浏览器发布到游客目录的联调尚待验收。

2026-11-13（旧数据兼容）：未修改编号时不提交元数据字段，保留旧格式编号或不透明元数据；实际修改编号时仍校验格式并保留其他 JSON 字段。重复已发布编号会使游客目录完整性检查失败，因此正式使用前仍需完成服务端发布约束和冲突处理。

2026-11-13（发布编号保护）：知识发布提交事务先锁定并更新知识状态，再检查本批草稿与其他已发布景点的 `attraction_id`；重复时整批失败、草稿保留。SQLite 测试覆盖批内和已发布冲突；已有历史重复、其他写入路径、PostgreSQL 并发和发布后编号变更仍需核查。向量预写可能留下不可见的孤儿记录，游客可见性仍以数据库发布版本为准。

2026-11-14（PostgreSQL 验证）：本机 PostgreSQL 17.11 临时空库执行 Alembic 迁移后，两个相同编号的发布任务并发执行，结果为一条成功、一条失败且失败草稿保留；另有现有测试观察到发布等待知识状态行锁。该测试使用合成数据和内存向量替身，并发测试本身未强制两个事务同时到达锁；真实业务库、其他写入路径及历史重复仍未验证。

2026-11-14（撤回锁顺序）：发现撤回原先先锁条目再锁知识状态，与发布顺序相反；现改为先更新知识状态行再撤回条目，缺少状态行时拒绝操作。临时 PostgreSQL 测试观察到撤回等待状态锁、释放前条目不变、释放后成功；相关 SQLite 和 PostgreSQL 测试 21 项通过。尚未证明所有其他写入路径不存在锁顺序冲突。

2026-11-14（SQLite 兼容）：发布、撤回和游客确认在 SQLite 使用存在性检查或事务末尾 epoch 更新，避免把 SQLite 粗粒度写锁误当作 PostgreSQL 行锁；PostgreSQL 仍先锁状态行。完整后端回归覆盖该调整并通过。

2026-11-14（数据库回归）：完整后端回归为 787 通过、20 跳过。临时 PostgreSQL 专项 14/15 通过；剩余 1 项在同一数据库串行运行多个测试时因旧测试留下已发布景点，导致“目录应为空”的测试隔离断言失败，单独全新数据库运行可通过。该失败不改变锁测试结论，但说明 PostgreSQL 专项必须每个测试使用独立数据库或清理数据。

2026-11-13：移植并调整 PDF 缺页检查。对每页提取文本；任意页无可提取文本时，整个文件进入 `needs_ocr`，保留原文件和失败任务，不生成部分草稿；提示页码供管理员核查。空白页和扫描页当前无法区分，因此空白页也会阻止导入，需人工处理后重导。扫描页若含少量或错误文本层仍可能通过检查，不能据此认定识别完整、准确或已实施 OCR。

验收：纯文本 PDF 保留页码并可进入草稿；混合文本/不可提取页面不得生成部分草稿，原文件保留并显示待核查页码；加密和页数限制维持既有行为。自动测试使用真实生成的混合 PDF 通过解析与导入链。Word/表格、图片识别、OCR、AI 理解与候选审核尚未整合或验收。

2026-11-13（DOCX）：管理端和上传存储支持 DOCX，通过 `python-docx` 按正文顺序提取段落与简单表格，标题分节并记录正文块位置，沿用 K01 来源版本、冲突及未发布草稿链。DOCX 解压大小和文件数受限；正文图片、嵌入对象、嵌套表格和合并单元格会拒绝并要求人工处理，避免静默丢失或重复。页眉、页脚、批注、脚注等不提取，页面明确提示管理员核对；不具备 OCR 或完整 Word 语义解析。自动测试使用生成的 DOCX 验证顺序、草稿和来源，以及复杂结构拒绝；真实文档和浏览器上传尚未验收。

2026-11-13（DOCX 浏览器验证）：本机 Chrome 在独立 SQLite、独立上传目录和合成 DOCX 上完成管理端登录、上传和任务完成；管理 API 确认本次任务生成的草稿含正文及表格且无发布版本，数据库检查确认草稿指向本次来源文档版本，游客问答 SSE 未出现该草稿版本。使用 stub LLM/TTS、本地 embedding、向量检索降级；并非真实资料或真实模型验收。脚本 `frontend/tests/e2e/docx-import-smoke.mjs` 只访问固定本机服务，需显式确认及合成 DOCX 路径，严禁用于真实业务库。

2026-11-13（XLSX）：管理端可导入工作簿，以每张表的首个非空行为表头，后续非空行分别形成带工作表/行号位置的未发布草稿，包括隐藏工作表及隐藏行列。公式、错误值、合并单元格、图片、图表、重复表头和无表头数据列会拒绝并提示人工处理；解压大小、单元格范围和数据行数量受限。表格样式、图表含义与公式计算不在解析范围，需人工核对。

数据行还受现有 `knowledge_import_max_pages` 导入段数上限约束，实际允许数量取两者较小值。

Word 正文块号与 XLSX 行号仅用于定位，不作为重导稳定身份：插行不会按位置覆盖已有草稿，但重新导入可能产生重复草稿，须由管理员核对。自动测试覆盖空行表头、草稿来源、复杂结构拒绝及插行不覆盖；浏览器上传、真实表格和 AI/OCR 尚未验收。

2026-11-13（人工编辑溯源）：导入草稿经人工编辑且来源说明未变时，新版本保留来源文档版本及页码/正文位置；管理端显示来源版本并提示内容可能修改，来源位置不证明修改后事实仍受原文支持。若管理员更换来源说明，旧文档关联及其导入身份元数据会清除。重导时有内容哈希的导入版本才作为自动匹配基线，人工编辑的新版本不会因此被直接覆盖；测试覆盖重导冲突和更换来源。模型候选、事实支持关系和真实资料审核仍未实现。

2026-11-13（本地 PDF OCR）：可选 OCR 默认关闭。需要预先安装 OCRmyPDF 与所选引擎，在本地后端配置 `KNOWLEDGE_OCR_ENABLED=true`、`KNOWLEDGE_OCR_EXECUTABLE` 为可执行文件绝对路径、`KNOWLEDGE_OCR_ENGINE=appleocr` 或 `tesseract`、`KNOWLEDGE_OCR_LANGUAGE` 为已安装语言；AppleOCR 仅在装有插件的 macOS 可用。当前只支持 POSIX，部署镜像未内置 OCR。需文本层的 PDF 先尝试正常解析；出现无文本页时才调用 OCRmyPDF `--skip-text`，原文件保留，输出在临时目录中处理并清理，成功结果进入未发布草稿，标记为包含 OCR 内容。解析失败、超时或处理后仍有无法提取文本的页不会生成部分草稿；空白页仍需人工处理。每个进程内限制同时一个 OCR 子进程，超时终止进程组；多进程全局并发、服务关闭时在途任务及 Windows 尚未验证。

自动测试覆盖关闭、失败、超时和标记；本机 OCRmyPDF 17.11.0 + AppleOCR 对合成英文扫描页的独立解析及隔离 SQLite 导入通过，生成的草稿关联原文并标记 OCR。识别结果空格有差异，中文、真实扫描文件、真实模型及浏览器管理流程尚未验收。OCR 文字仅为机器识别，管理端和理解预览均提醒对照原文件，不等同事实审核。
