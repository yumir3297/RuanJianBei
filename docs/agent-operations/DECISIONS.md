# Current-round decisions and held scope

Updated: 2026-11-07.

| Decision | Basis | Consequence |
|---|---|---|
| Use `origin/codex/competition-integration@7ef0459` as the source baseline and continue on `integration/ai-workbench-final`. | It contains the selected K01/map lineages and the largest validated integration body; current `master` is not the development baseline. | Never change master directly. Delivery is a PR against `codex/competition-integration`. |
| Keep all four workspace snapshot refs and the location/offline branch intact; do not merge snapshots by name. | Snapshot commits preserve file states, but differ from later code. Historic audit compares implementation and behavior, not just branch labels. | No snapshot cherry-pick was justified by the current UI delta review. |
| Do not copy the W02 snapshot Alembic migration. | It reuses `f1b4c9d76e20` with a different parent and omits itinerary proposal execution fields; current integration merges migration heads and has subsequent lineage guards. | Validate the current single head; deployed database compatibility remains an external gate. |
| K01 publication recovery must be explicit and idempotent. | A lost POST response is ambiguous; same request items and key are persisted before POST. | Known job ID: status GET on refresh. Unknown result: show “recover” action, re-submit only with the original key after user action. Never create a second key or auto-retry. Refuse to POST if session storage cannot persist the record. |
| Treat clear 4xx create responses as rejected; keep timeout/429/5xx outcomes recoverable. | The publication service validates selection/version/conflicts before committing the queued job; those 4xx responses do not create a new job. | Clear the rejected pending key and let the operator reload/reselect the draft. For a retry POST with an unknown response, GET the known job before deciding whether retry remains needed. |
| Polling stops on view unmount, including an in-flight GET. | An in-flight GET is read-only but must not schedule a new timer or mutate an unmounted view. | Workflow dispose suppresses callbacks and rescheduling; server state is untouched. |
| Keep code map feature-oriented and correct stale K01/architecture claims in place. | Existing `docs/REPO_MAP.md` and checker are useful; they had a stale claim that CRUD did not use revisions and K01 recovery was only an unapplied patch. | Update the existing map rather than creating another map system; preserve the checker. |
| Pin `pytest-asyncio` next to pytest in backend requirements. | Baseline command without this plugin collected 49 async tests as failures, although all those tests passed when the plugin was installed. The repo declares pytest but omitted its async runner. | Tests become reproducible from declared requirements; no app runtime behavior changes. |
| Use DeepSeek for vision and Bailian Fun-ASR (not a Qwen model) for cloud ASR. | DeepSeek's official Vision guide documents `deepseek-flash` image inputs using OpenAI-compatible image blocks. Alibaba Model Studio documents Fun-ASR dialect support. Code review found the former Qwen-ASR config URL/payload/parser did not match the documented Qwen3-ASR API contract. | The active vision adapter is DeepSeek `deepseek-flash`; active cloud ASR is Bailian `fun-asr`. The Bailian file-transcription route needs a public HTTPS audio URL; optional precompiled vocabulary uses `ASR_VOCABULARY_ID`. Local SenseVoice/stub remain. TTS remains Volcengine in this scope. Real provider calls are not made in tests. |
| Use the repository's processed guide-section JSON for plumbing acceptance, not as certified scenic truth. | GitHub contains 22 `data/processed/guide_sections.json` rows and other Lingshan-related processed files; README labels these as examples and requires source/permission checks. The raw visitor-behavior spreadsheet is not needed for K01 workflow testing. | A temporary SQLite acceptance test imports and publishes the 22 guide sections with fake vectors. It does not validate factual accuracy, permissions, live RAG quality, or real embeddings. Avoid the behavior spreadsheet until privacy/authorization is confirmed. |
| Treat the discovered local OCR tool as a candidate, not an integrated backend capability. | `~/Documents/pdf-ocr-mac/ocr-pdf` is an external shell wrapper around OCRmyPDF + `ocrmypdf-appleocr` using macOS Apple Vision; its README also describes sidecar text output. Homebrew OCRmyPDF 17.11.0 and the AppleOCR options are installed locally. | It is macOS-only and writes a searchable PDF; it is not part of this repository or the application API. Accuracy, page-level source mapping, resource/timeout behavior and integration with the persistent K01 import job are unverified. Linux/Windows deployment needs a separate engine/adapter or a different deployment design. No real document was processed. |
| Keep full CASS and offline delivery out of this implementation change. | Only `feat/location-guide-opt` contains a CASS proposal and offline implementation; that branch's map is a placeholder and example hotline resources are not verified, while backlog E04/CASS work is not confirmed as a production safety spec. | Preserve it for a separate design/evidence gate. Never show simulated coordinates, crowd estimates, placeholder maps, or unverified numbers as official safety facts. |
| Do not claim G1–G6 fully complete based on automated proxies. | No real iOS/Android/WeChat device, cloud AI/TTS keys, or production database is available here; W03/O01 and several planned tasks are also not implemented. | Final status must be `PARTIAL` unless those boundaries are closed by actual evidence. |
