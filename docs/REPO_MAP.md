# AI 数字人导览：功能与代码地图

集成工作副本：来源包含 V01 与主工作区，正在合并，路径与行为须在最终集成后重新验证。
本文件说明定位和验证入口；不代表下列功能均已在真实设备或外部服务上通过验收。
2026-10-29 补充：评委体验验收发现并修复 1000–1399px 桌面窗口下地图栏过窄的问题；验收范围、实测结果与未覆盖边界见[评委体验验收记录](superpowers/plans/2026-10-29-judge-experience-acceptance.md)。
所有链接相对仓库，适用于 GitHub、本地编辑器及能读取 Markdown 的代码助手。

## 使用方法

1. 按用户任务找到功能行，先读 UI 入口及对应 API，再沿服务和数据层定位。
2. 涉及跨层修改时看 [架构](ARCHITECTURE.md)；启动和测试看 [开发指南](DEVELOPMENT.md)。
3. 涉及手机、平板、桌面或浏览器能力时看 [兼容性矩阵](COMPATIBILITY.md)。
4. 修改后更新相应行，并执行 `python scripts/check_repo_map.py`。
5. `python scripts/check_repo_map.py --json` 从当前源码导出实时 API 索引；它不是 OpenAPI，也不包含完整调用图。

按下表逐层核对；当前游客检索只使用当前发布 revision。草稿、导入中间结果与未发布向量均不可见；发布任务结束后还应按对应 revision 检查来源。

| 层次 | 直接定位 | 当前边界 |
|---|---|---|
| 草稿与修订 | [knowledge.py](../backend/app/api/knowledge.py) → [KnowledgeWorkspaceService](../backend/app/services/knowledge/workspace.py) → [KnowledgeEntry/KnowledgeRevision](../backend/app/models/knowledge_workspace.py) | 新增、编辑写入草稿 revision；游客可见指针不随草稿写入改变。检查 `draft_revision_id`、`published_revision_id` 与 `lock_version`，确认编辑基于期望版本。 |
| 文件导入与冲突 | [knowledge_imports.py](../backend/app/api/knowledge_imports.py) → [KnowledgeImportService](../backend/app/services/knowledge/imports.py)、[parsers](../backend/app/services/knowledge/parsers.py)、[ImportBatchRepository](../backend/app/repositories/knowledge_workspace.py) | 导入任务与冲突持久保存；现有解析器支持 JSON/文本层 PDF，扫描 PDF 返回 `needs_ocr` 而非发布空内容。核对批次状态、幂等键、文档版本与人工冲突决议。 |
| 发布任务 | [knowledge_publications.py](../backend/app/api/knowledge_publications.py) → [KnowledgePublicationService](../backend/app/services/knowledge/publication.py) | 请求固定 entry/revision/expected_version 并建立持久任务；准备失败不切换发布指针，发布过程产生的后续草稿不会混入该任务。以发布任务状态和数据库发布指针为准，不以 HTTP 请求已返回判断完成。 |
| 分块与向量 | [KnowledgeChunkRepository](../backend/app/repositories/knowledge_chunk.py)、[RAGIndexBuilder](../backend/app/services/rag/index_builder.py)、[visibility](../backend/app/services/knowledge/visibility.py) | 按 revision 构建分块/向量；检索候选仍须由数据库发布版本校验。全量重建通过安全的新集合切换，不能把直接删除当前集合作为恢复步骤。 |
| 答案缓存与流式证据 | [QACache](../backend/app/services/qa/cache.py)、[StreamEvidenceRun](../backend/app/services/qa/stream_evidence_run.py)、[QAPipeline](../backend/app/services/qa/pipeline.py) | 知识 epoch 进入缓存键与生成/完成阶段的可见性 fence；epoch 变化时拒绝旧证据继续定稿或写入。真实多进程部署、Chroma 并发与旧数据库迁移仍需单独验证。 |

完整本地自动化覆盖发布/下架、失败恢复、可见性过滤、epoch 与向量重建；可以从上述专项测试定位。此地图不证明当前景区资料权威、真实模型回答忠实、部署数据库迁移无风险或真实多实例并发安全。
