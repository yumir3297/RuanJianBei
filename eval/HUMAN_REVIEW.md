# 人工核验：回答事实与证据

本方法用于真实服务运行后的逐题核查；没有真实运行和标注时，不得填写或推算结果。自动评测中的关键词命中和引用标记仅用于筛查，不表示事实正确或证据支持。

## 固定输入

保存代码提交、题集 SHA256、抽样算法和种子、题目 ID 顺序、知识发布版本、模型及参数、供应商、时间、测试设备、网络条件、缓存状态和可追溯的请求结果。确认资料的来源、时间和使用权限；清除个人信息及密钥后保存。将整个样本、请求失败及缺失结果纳入记录，不只挑选成功答案。

## 每题人工标注

两名评审独立读取原题、回答、返回资料与引用位置，逐项记录。字段可以保存为下列 JSON；`null` 表示未评、无法判断或不适用，不能当作成功。

```json
{
  "case_id": "题集ID",
  "reviewer": "评审代号",
  "execution": "completed | error | incomplete",
  "expected_behavior": "answer_with_evidence | refuse_without_evidence",
  "answer_factually_correct": null,
  "refusal_appropriate": null,
  "claims": [
    {"text": "需核验的具体陈述", "citation_ids": ["证据1"], "citation_resolves": null, "supported_by_cited_text": null, "notes": "依据及定位"}
  ],
  "uncited_material_claims": [],
  "notes": "不确定性、来源时间或失败原因"
}
```

对每个可核验的重要事实陈述：检查标记是否指向该回答实际返回的资料，资料是否明确支持该陈述，以及资料本身是否可靠、适用和及时。缺引用、编号不存在、资料无关、资料过时、资料支持与否无法判断，分别记录，不能通过“资料列表非空”推定支持。无资料时依据题目预期判断是否恰当拒答；不应因出现固定拒答词就自动判对。带推断或未核实的信息应检查其措辞是否清楚。

分别记录 A/B 评审分歧并复核原资料；一致性与最终裁定均保留。测试者知道这是评审但不应预先看到方案名称或指标排名。资料本身无法核实的题记录为未知，并说明原因。

## 汇总与对照

- **任务完成率**：达到预定可观察结果的题数 / 全部执行题数；失败、超时列入分母。定义哪些题适用任务完成，并保留原始计数。
- **证据支持率**：经评审判定被所引用资料支持的事实陈述数 / 所有已完成核验的带引用事实陈述数；另列未引用、错误编号、无法判断和未完成核验的数量。它不是全部事实的正确率。
- **事实正确率与拒答**：分别给出已裁定的正确数、错误数、无法判断数；报告应拒答题与应回答题各自的误答/误拒，不能将缺失结果计为通过。
- **耗时与成本**：同一题集和环境逐题记录首字、完成耗时及实际调用次数/token/费用；标明失败、超时、FAQ/缓存命中和冷暖条件。样本不足时展示所有原始值，不夸大 P95 的稳定性。
- **方案对照**：固定资料、模型、参数、设备及题目顺序，以同一标注规则记录前后版本；说明变化、实际样本量和失败。分层均衡样本不按总体分布抽取，未经适当加权不能代表全题总体表现。

不要把 fake provider、dry-run、单次 smoke、模型自评或模型返回的 confidence 冒充真实服务的事实准确率。生成最终竞赛图表前，核对原始运行记录、人工裁定和对应提交。
